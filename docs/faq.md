# 常见问题（FAQ）

这一页只回答「用的时候真的会卡住人」的问题。每一条都给出**判断依据**，而不是「请阅读文档」。

---

## 1. 需要联网吗？要花钱吗？

分三种情况：

| 场景 | 网络 | 花费 |
| --- | --- | --- |
| `pcause demo`（内置演示） | 不需要 | ¥0 |
| `npm test` / `pcause selftest` | 不需要 | ¥0 |
| 真实归因（`--provider deepseek` 或任意真实模型） | 需要 | 按模型的 token 计费；一次演示规模约 24–60 次请求 |

`--verify doubao` 会复用你已登录的豆包桌面版，不需要 API Key，但会占用一个窗口、每次 5–15 秒。

## 2. `0% 无影响` 是什么意思？是「没测」吗？

不是。报告里「无影响（0%）」的意思是：**把这一块改动回退掉之后，探针上的输出在判定口径下没有发生实质变化**。

要区分两个词：

- `无影响（inert）`：测了，而且多次采样下变化率与噪声地板相当；
- `未测（unmeasured）`：预算/采样不足以判断，报告会单独标注，**不能当成无影响**。

如果整份报告里所有块都是 0%，先怀疑探针没有覆盖被改动的行为（见第 4 条），而不是「提示词没用」。

## 3. 同一个实验跑两次，结论为什么不一样？

因为模型本身不确定。实测 DeepSeek 在 `temperature=0` 下，同一提示词连续请求仍可能返回不同输出；pcause 用「噪声地板」量化这种波动，再用 `effect = max(0, (c − w) / (1 − w))` 做校正（`c`=组间变化率，`w`=组内变化率）。

判断依据（都在报告顶部/表格里）：

- 噪声地板越高，结论越不可信；报告会亮「稳定性警告」；
- 第二意见（`--verify`）一致率低，说明判定本身摇摆；
- 提高 `--samples` 能让噪声地板更准，但花费线性增长。

## 4. 结果和直觉不一致，先检查什么？

按顺序看三件事：

1. **证据区**：每个块下面有逐探针的「新版输出 vs 回退后输出」。如果两者只是措辞不同，被判定为 changed 才有问题；
2. **探针是否覆盖该行为**：探针是「输入样本」，改的是语气、就要有能体现语气的输入；
3. **hunk 是否被合并**：相邻改动之间如果没有公共行，diff 会把它们合并成一个块，归因粒度就变粗了。`pcause diff <old> <new>` 能直接看到块数。

## 5. 能测 system prompt 或 Agent 指令吗？

`--kind system|agent` 会切换判定器关注的维度（system 偏规则边界/安全拒答/格式刚性，agent 偏目标达成/工具策略/终止条件），并在报告里标注「假设可信度」。

注意：`kind` 目前是**元标签 + 判定维度适配**，它不改变消融流程，也不做结构化分维度打分。因此 `system` 的结论仍然依赖探针覆盖——探针里要包含「本应被拒绝/本应走异常分支」的输入。

## 6. 一次实验要多少调用？预算怎么控？

先跑预估（不产生任何请求）：

```bash
node src/cli.mjs attribute --old review-v1 --new review-v2 --probes examples/probes.jsonl --dry-run
```

它按「改动块数 × 探针数 × 采样数」估算生成/判定/复核次数与上限。实跑时：

- `--max-calls <n>` 是硬上限（预算预占，超了会把块标成 `unmeasured`，而不是偷偷少跑）；
- 内容寻址缓存让重复实验几乎不花钱（相同 provider/模型/提示词/输入直接命中）；
- `--concurrency` 只影响速度，不影响调用总数。

## 7. 能接进 CI 吗？

可以，且不需要模型 Key（用离线自测或已缓存的实验）：

```bash
node src/cli.mjs attribute ... --json-out result.json --fail-on decisive
```

- `--json-out` 产出符合 `schema/attribution.schema.json` 的机器可读结果；
- `--fail-on decisive|partial` 命中时退出码 `2`（业务门禁），采样不足的块不参与门禁；
- 普通错误退出码 `1`，成功 `0`——CI 只看退出码即可区分「结论命中」和「工具坏了」。

## 8. 为什么 CSV/JSON 里有一些块是 `unmeasured`？

三种原因：`--max-calls` 预算不够、判定调用失败后降级、采样数不足（块级判定需要至少 2 次采样）。这些块要么追加预算/采样后重跑，要么直接当作「本轮没结论」，不要写进结论汇总。

## 9. 怎么判断这份报告可信？

四个数一起看，缺一不可：

| 信号 | 好 | 需要警惕 |
| --- | --- | --- |
| 噪声地板 | < 15% | ≥ 34%，报告会亮警告 |
| 采样数 | ≥ 2/探针（自适应会补到 3） | 1 次，无法估计噪声 |
| 第二意见一致率 | 接近 100% | 明显低于 100%，判定在摇摆 |
| 证据区 | 能看到行为差异 | 只有措辞差异，或输出为空 |

## 10. 为什么报告里出现了「没有差异」的报错？

`PCAUSE_NO_DIFF` 不是错误，是正常结果：新旧提示词在文本层面完全一致（常见于复制粘贴时多了/少了空白或换行）。pcause 会明确告诉你「没有可消融的改动块」，退出码 `1`。
